# RAVAN AI — Android + web deployment

RAVAN is the existing desktop assistant, moved onto a phone without rewriting
the assistant. The Gemini model, the system prompt, the character and the mouth
animation are the same code and the same data the desktop uses; the new parts
are a FastAPI bridge, a responsive web interface, and a Capacitor Android shell
with native intents and a floating orb.

```
┌──────────────────────────────┐        ┌───────────────────────────────┐
│ Android APK (Capacitor)      │        │ Render — FastAPI              │
│  WebView: web/ (same files   │ HTTPS  │  server/app/                  │
│  GitHub Pages serves)        │───────▶│   ├─ core/prompt.txt          │
│  STT/TTS: Android engines    │ bearer │   ├─ core/gemini.py (ladder)  │
│  Kotlin: intents, overlay    │        │   ├─ core/viseme.py           │
└──────────────────────────────┘        │   └─ in-memory sessions       │
┌──────────────────────────────┐        └───────────────────────────────┘
│ GitHub Pages — static web/   │───────────────────────▲
│  index.html, ES modules      │        same API       │
└──────────────────────────────┘
```

The desktop app (`main.py`, `ui.py`, `core/avatar.py`, …) is untouched and still
runs from the root `requirements.txt`.

---

## What was reused, not rebuilt

| Piece | Source | How the phone uses it |
| --- | --- | --- |
| Assistant behaviour | `core/prompt.txt` | Reused with the same substitutions; only the "desktop" sentence is adapted for a phone (`server/app/prompt.py`). |
| Model + fallback ladder | `core/gemini.py` | Called unchanged from `server/app/ai.py`; no second AI implementation. |
| Mouth shapes | `core/viseme.py` | The server returns `visemes` with every reply; the client animates them. |
| Character geometry | desktop head mesh | Exported once by `server/tools/export_head.py` to `web/assets/head.json` (810 vertices, 1554 faces). The web renderer uses the same landmarks and rigs. |
| Tool contract | desktop action registry, reduced | Four phone-safe actions in `server/app/tools.py`; the APK executes intents, the server only validates. |

There is no database and no second model key. `config/api_keys.json` is never
read by the server and never copied into the APK.

## Repository layout

```
web/                 static frontend (ES modules, no build step, no CDN)
server/app/          FastAPI: health, chat, tools, sessions, prompt adaptation
server/tests/        contract tests, runnable in mock mode without a key
server/requirements.txt   cloud-only dependencies
scripts/build-web.mjs     copies web/ → www/ and bakes RAVAN_BACKEND_URL
scripts/make_icons.py     regenerates the launcher icons
android/             Capacitor Android project + Kotlin plugin and overlay
deployment/smoke_test.py  health/chat/dedupe check for a deployed backend
.github/workflows/pages.yml   builds and deploys web/ to GitHub Pages
render.yaml          Render Blueprint (one web service, no database)
capacitor.config.json
```

`www/` and `android/app/src/main/assets/public/` are generated by
`npm run build:web` / `npm run sync` and are gitignored. The desktop files
(`main.py`, `ui.py`, `core/`, `actions/`, …) stay in the repo unchanged; the
server only imports from them.

## 1. Run it locally

Backend (mock mode needs no API key and makes no network calls):

```bash
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r server/requirements.txt

# Deterministic replies for UI work:
RAVAN_MOCK=1 python -m uvicorn server.app.main:app --host 127.0.0.1 --port 8765

# With the real model:
GEMINI_API_KEY=... python -m uvicorn server.app.main:app --host 127.0.0.1 --port 8765
```

Open <http://127.0.0.1:8765/app/>. The backend serves the same `web/` folder that
Pages deploys, so local testing and production differ only by URL.

Desktop app (unchanged): `pip install -r requirements.txt` then `python main.py`.

## 2. Deploy the backend on Render

**Blueprint:** push the repo, then Render → **New → Blueprint** → pick the repo.
`render.yaml` creates one free web service:

- build: `pip install -r server/requirements.txt`
- start: `uvicorn server.app.main:app --host 0.0.0.0 --port $PORT`
- health check: `/health`

Then set in **Environment**:

| Variable | Value |
| --- | --- |
| `GEMINI_API_KEY` | your key (secret; never commit it) |
| `RAVAN_API_TOKEN` | long random string, e.g. `openssl rand -hex 32` (recommended) |
| `ALLOWED_ORIGINS` | `https://YOURNAME.github.io,https://localhost` |
| `RAVAN_MOCK` | `0` for live answers, `1` for canned demo replies |

Manual setup instead of a Blueprint: Web Service → Python 3.12 → the build/start
commands above → health check `/health`. No disk, no database, no GPU.

Notes:

- The free instance sleeps; the first request can take ~30–60 s. The UI retries
  network/timeout three times and then shows a Retry banner.
- Sessions live in memory: restarting the service clears conversations. That is
  deliberate — there is nothing to migrate and nothing to back up.
- `https://localhost` must stay in `ALLOWED_ORIGINS`: it is the APK WebView's
  origin, not a typo.

Verify a deployment:

```bash
python deployment/smoke_test.py https://YOUR-SERVICE.onrender.com --token YOUR_TOKEN --chat
```

## 3. Deploy the web frontend to GitHub Pages

1. Repo → **Settings → Pages → Build and deployment → Source: GitHub Actions**.
2. Repo → **Settings → Secrets and variables → Actions → Variables → New variable**:
   `RAVAN_BACKEND_URL = https://YOUR-SERVICE.onrender.com`.
3. Push to `main` (or run the workflow manually). `.github/workflows/pages.yml`
   writes `web/config.js` with that URL and publishes `web/`.
4. The site appears at `https://YOURNAME.github.io/REPO/`. All paths are
   relative, so a project subpath works without changes.

The workflow never writes a token: the access token is entered on the device in
**Settings** and kept in that browser's `localStorage`.

If `RAVAN_BACKEND_URL` is left empty the page still loads and asks for the URL
in Settings (the workflow prints a warning). Static hosting cannot run Python —
Pages serves only the interface; the assistant always runs on Render.

To publish manually instead:

```bash
git add .
git commit -m "Deploy RAVAN mobile"
git remote add origin https://github.com/YOURNAME/REPO.git
git push -u origin main
```

## 4. Build the Android app

Prerequisites: Node 20+, Android Studio (SDK 36, JDK 21 — bundled with current
Studio). This repository was scaffolded with Capacitor 8.6.0.

```bash
npm install
RAVAN_BACKEND_URL=https://YOUR-SERVICE.onrender.com npm run sync
npx cap open android
```

`npm run sync` runs `scripts/build-web.mjs` (copies `web/` to `www/`, writes
`www/config.js`) and then `cap sync android`. On PowerShell:

```powershell
$env:RAVAN_BACKEND_URL="https://YOUR-SERVICE.onrender.com"; npm run sync
```

Without a baked URL the app opens with "No backend configured" and Settings can
still supply one on the device.

**Debug APK:** Android Studio → *Build → Build App Bundle(s) / APK(s) → Build
APK(s)*; output `android/app/build/outputs/apk/debug/app-debug.apk`.

Or from the command line, from `android/`:

```bash
./gradlew assembleDebug          # Windows: gradlew.bat assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

**Signed release** (do this once; keep the keystore out of git — it is already
ignored):

```bash
cd android
keytool -genkeypair -v -keystore ravan-release.jks -alias ravan \
        -keyalg RSA -keysize 2048 -validity 10000
```

Create `android/keystore.properties` (gitignored):

```properties
storeFile=ravan-release.jks
storePassword=…
keyAlias=ravan
keyPassword=…
```

Then:

```bash
./gradlew assembleRelease        # Windows: gradlew.bat assembleRelease
# android/app/build/outputs/apk/release/app-release.apk
```

`app/build.gradle` reads the properties file only if it exists; without it the
release build is unsigned and the debug build is unaffected. Losing the keystore
means you cannot update an installed app, so back it up privately.

App identity: `ai.ravan.assistant`, minSdk 24, targetSdk 36, no cleartext
traffic, dark launch theme, generated orb launcher icons.

### Rebuilding web assets after an edit

```bash
RAVAN_BACKEND_URL=https://… npm run sync   # update the APK copy
```

## 5. What the phone build can and cannot do

| Capability | Web / Pages | Android APK |
| --- | --- | --- |
| Assistant replies, animated face, visemes | yes | yes |
| Voice in (OS speech recogniser) | Web Speech where supported | Android recogniser |
| Voice out (TTS) | `speechSynthesis` | Android TTS engine |
| Open allowlisted apps | opens the website | real intents |
| Open https links | new tab | browser intent |
| YouTube | search page | YouTube search intent |
| WhatsApp | `wa.me` composer | `wa.me` composer in WhatsApp |
| Floating orb over other apps | — | yes, native overlay |
| Continuous listening in background | — | not implemented |
| Files, screenshots, desktop automation, Gmail/Calendar tools | — | — |
| Long-term memory | — | — (session only) |

Allowlisted apps: chrome, youtube, whatsapp, settings, downloads, camera, maps,
gmail, spotify, instagram, telegram, calculator, clock. Missing apps return
"not installed" instead of opening a store page silently.

### WhatsApp is composer-only

The confirmation sheet shows the contact (a phone number, or "choose a contact
in WhatsApp") and the message. Confirming opens WhatsApp with the text ready —
RAVAN never sends, because sending would require an unverifiable tap. There is
no accessibility automation, no notification scraping and no contact access; an
ambiguous contact can never be messaged by the assistant.

### YouTube is search-only

The action opens search results for the requested title. It does not claim a
video is playing, and this build has no media controls. DRM and downloads are
not touched.

### Floating orb

Settings → **Floating RAVAN icon**. The first enable request opens Android's
"display over other apps" screen; the permission is requested only for this
feature and is explained in the sheet. The orb is a Kotlin `View` in a
`TYPE_APPLICATION_OVERLAY` window inside a foreground service:

- drag to move, position remembered;
- tap to open/restore RAVAN;
- mic badge toggles mute and syncs to the app;
- close badge (top-left) hides it and updates the setting;
- notification with Open / Hide; the service stops with the orb, no zombie.

The service uses the `specialUse` foreground-service type (Android 14+ requires
a type) and a low-importance notification. It does not use accessibility
services and reads nothing on screen.

## 6. Permissions

| Permission | Why |
| --- | --- |
| `INTERNET` | talk to Render |
| `RECORD_AUDIO` | one-shot speech recognition after a mic tap |
| `SYSTEM_ALERT_WINDOW` | the floating orb, only when enabled |
| `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_SPECIAL_USE` | keep the orb alive |
| `POST_NOTIFICATIONS` | the orb's Open/Hide notification (Android 13+) |

No contacts, storage, location, SMS, accessibility, or "all files" access. No
password, token or signing key is compiled into the APK. The WebView blocks
cleartext HTTP and runs only bundled same-origin code.

## 7. State, data and retention

- **Server:** conversations are in memory only (TTL 30 min, 24 turns kept, 200
  sessions max). Restarting clears them. Request text is not logged.
- **Phone/browser:** the visible transcript is not persisted; the session id
  lives in `sessionStorage`; backend URL, optional token and preferences live in
  `localStorage` on that device. "Exit RAVAN" stops the overlay and the task.
- **Model provider:** prompts and replies are sent to Google's Gemini API and
  are subject to Google's API terms. This project cannot promise zero retention
  on the provider side, and does not claim to.

Duplicate protection: the client sends a `request_id`, the server caches replies
per id for five minutes, and a per-session lock rejects overlapping turns with
409. A dropped connection retried by the client therefore produces one answer
and one spoken reply, not two.

## 9. Troubleshooting

| Symptom | Check |
| --- | --- |
| Page loads, says OFFLINE | Render asleep (wait ~60 s, Retry), wrong `RAVAN_BACKEND_URL`, or CORS |
| `401` / "requires an access token" | enter `RAVAN_API_TOKEN` in Settings (same value as Render) |
| CORS error in the browser console | add the exact origin (`https://user.github.io`, `https://localhost`) to `ALLOWED_ORIGINS` |
| `503` "model could not be reached" | missing/invalid `GEMINI_API_KEY`, or provider quota |
| Face area blank | `web/assets/head.json` was not deployed; check the Pages artifact and console |
| Mic does nothing | permission denied, or the browser has no Web Speech (Firefox) — typing still works |
| No speech | Android TTS engine has no voice data; the UI still shows replies |
| Floating icon won't start | overlay permission not granted, or battery optimisation killed the service |
| WhatsApp opens without contact | expected for a name: pick the contact in WhatsApp; numbers must include country code |
| "app is not installed" | package not present, or OEM build renamed it; the allowlist is fixed |
| APK shows no backend | rebuild with `RAVAN_BACKEND_URL`, or set the URL in Settings |
| Stale JS after a deploy | the backend serves `Cache-Control: no-cache`; in the APK run `npm run sync` |

## 10. Security notes

- Secrets belong in the Render dashboard and in `android/keystore.properties`;
  both are gitignored. `.env.example` contains placeholders only.
- The bearer token is a header, not a cookie; CORS is pinned per origin.
- The server validates every tool call again (`server/app/tools.py`) even though
  the model produced it; the WebView validates again before an intent.
- URLs are https-only end to end; `usesCleartextTraffic="false"`.
- There is no shell execution, no desktop automation, no accessibility scraping,
  no arbitrary package launch, and no message send anywhere in the mobile build.
